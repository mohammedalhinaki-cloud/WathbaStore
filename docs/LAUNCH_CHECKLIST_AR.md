# وين الموقع الحقيقي؟ — حالة النشر الآن وما ينقص بالضبط

> ملف عملي قصير. الدليل الكامل خطوة بخطوة للنشر موجود في [`DEPLOY_VERCEL_AR.md`](DEPLOY_VERCEL_AR.md).

## 1) الخلاصة في أربع نقاط

1. **الموقع الرسمي المفترض هو `wathbastore.com` — وهو غير مربوط بعد.** لا يوجد له أي سجل DNS
   (`wathbastore.com` و`www.wathbastore.com` و`rshaf.wathbastore.com` لا تُحلّ إلى أي عنوان)،
   لذلك لا يفتح أي منها الآن. كل «المتاجر» في المنصة تعيش على `*.wathbastore.com`، فبدون هذا
   الدومين لا يوجد موقع حقيقي للمتاجر — حتى لو كان الكود منشورًا بنجاح.
2. **الرابط الذي بين يديك (`wathba-store-….vercel.app`) هو نشر الإنتاج لنفس المنصة**، لكن على
   **عنوان مؤقت** من Vercel. هو ليس «موقعًا تجريبيًا منفصلًا عن الكود»، بل نفس الكود على نطاق مؤقت.
3. **قاعدة Supabase مربوطة فعلًا في هذا النشر** (المحتوى الظاهر: الباقات والعروض والإعدادات يأتي
   من جداول Postgres في مشروعك، وليس من بيانات مضمّنة في الكود). لكن **حساب المالك لم يُنشَأ في
   Supabase Auth ولم يُرقَّ إلى `owner`**، وهذا سبب عدم قدرتك على الدخول إلى `/admin`.
4. **على عنوان المعاينة المُؤقت لم تكن محاكاة النطاق الفرعي (`?store=`) تعمل**، لأن كشف المستأجر
   كان يعتبر نطاق `vercel.app` نفسه هو «الدومين الرئيسي». **أُصلح هذا الآن في الكود**؛ بعد إعادة
   النشر على Vercel يمكنك فتح متاجر العملاء على العنوان المؤقت نفسه:
   - متجر رشف: `https://<your-project>.vercel.app/?store=rshaf`
   - لوحته: `https://<your-project>.vercel.app/admin?store=rshaf`

## 2) ما ينقص بالضبط (بالترتيب)

### أ) إنشاء حساب المالك في Supabase

- [ ] **Supabase → Authentication → Users → Add user**: أنشئ مستخدمك ببريدك الحقيقي وكلمة مرور قوية،
      وفعّل تأكيد البريد إن ظهر الخيار.
- [ ] **SQL Editor** — استبدل البريد ثم شغّل:

```sql
update public.profiles
set role = 'owner'
where lower(email) = lower('you@example.com');

-- تحقق: يجب أن يظهر صف واحد فقط بدور owner
select email, role from public.profiles order by created_at;
```

- [ ] جرّب الدخول: `https://<your-project>.vercel.app/admin` → لوحة المالك.
- [ ] (لدعم المتاجر التجريبية) أنشئ حسابَي العرض إن رغبت:
      `rshaf@demo.com / Rshaf#2026` و`oud@demo.com / Oud#2026`، ثم أعد تشغيل قسم
      **ربط حسابات العملاء** في `supabase/migrations/0002_demo_data.sql`.

> لا يوجد أي تسجيل عام في المنصة: حساب المالك لا يُنشَأ من الموقع، بل من لوحة Supabase كما فوق.

### ب) التحقق من متغيرات Vercel

- [ ] **Vercel → Project → Settings → Environment Variables** (Production وPreview):

| المتغيّر | القيمة الصحيحة | ملاحظة |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | `https://xxxxxxxx.supabase.co` | رابط المشروع فقط — بلا `/rest/v1` وبلا تنصيص |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | `sb_publishable_…` | عام |
| `SUPABASE_SECRET_KEY` | `sb_secret_…` | خادم فقط — يُستخدم لإنشاء حسابات العملاء عند التسليم |
| `NEXT_PUBLIC_MAIN_DOMAIN` | `wathbastore.com` | ⚠️ **لا تجعلها نطاق `vercel.app`**، وإلا تعطّل فصل المتاجر على الدومين الحقيقي |
| `DEVELOPER_URL` | `https://wathbastore.com` | رابط التوقيع أسفل كل متجر |

- [ ] بعد أي تعديل: **Redeploy** — قيم `NEXT_PUBLIC_` تُدمج وقت البناء ولا يسري التعديل وحده.

### ج) ربط الدومين (الخطوة التي تصنع «الموقع الحقيقي»)

- [ ] املك الدومين: إن لم يكن `wathbastore.com` مسجّلًا باسمك، اشترِه أولًا. وإن أردت نطاقًا آخر
      (مثل `wathba.sa` أو نطاق تملكه) فحدّث `NEXT_PUBLIC_MAIN_DOMAIN` وحده وستتحول كل المتاجر
      تلقائيًا إلى `name.<النطاق الجديد>`.
- [ ] **Vercel → Project → Settings → Domains** → أضف:
      1. `wathbastore.com`
      2. `www.wathbastore.com`
      3. `*.wathbastore.com`  ← هذا هو الذي يُشغّل `rshaf.` و`oud.` وكل متجر جديد بلا أي إعداد لاحق
- [ ] طبّق سجلات DNS التي يعرضها Vercel (الأسهل: استخدام nameservers الخاصة بـ Vercel)، وانتظر
      حتى تصبح الحالتان **Valid Configuration** وتُصدر شهادات HTTPS.
- [ ] اجعل `wathbastore.com` نطاق الإنتاج الأساسي (Production).

### د) التحقق النهائي

- [ ] `https://wathbastore.com` → الموقع العام.
- [ ] `https://wathbastore.com/admin` → دخول المالك بحسابك الجديد.
- [ ] `https://rshaf.wathbastore.com` → متجر رشف، و`https://rshaf.wathbastore.com/admin` → لوحة العميل.
- [ ] من لوحة المالك: **إنشاء متجر** → تجهيز → **تسليم** → يظهر حساب العميل وكلمة مروره.
- [ ] لاحظ أن شريط التنبيه الأصفر (نسخة معاينة / قاعدة بيانات غير مربوطة) **يختفي تلقائيًا**
      على الدومين الرسمي بعد نجاح الربط — لأنه لا يظهر إلا على نطاقات المعاينة أو عند غياب Supabase.

## 3) هل يمكن الاستفادة من نشر Vercel دون دومين؟

نعم بشكل محدود: العنوان المؤقت يصلح للعرض والاختبار داخليًا (`?store=rshaf`)، ويصلح لدخول لوحة
المالك، لكنه **لا يصلح للتسليم للعملاء**: لا نطاقات فرعية على `vercel.app`، ولن يعمل
`rshaf.<...>.vercel.app`. التسليم الحقيقي يحتاج دومينًا تملكه + `*.الدومين` في Vercel.

## 4) لماذا لا يستطيع المالك الدخول؟ (تشخيص سريع)

| العَرَض | السبب المرجّح | الحل |
|---|---|---|
| «بيانات الدخول غير صحيحة» على عنوان Vercel | الحساب غير موجود في `auth.users` أو غير مُرقّى في `profiles` | نفّذ الخطوة (أ) |
| الدخول ينجح ثم يعود لصفحة الدخول | لا صف في `public.profiles` لحسابك، أو كوكيز الجلسة محجوبة | نفّذ استعلام التحقق في (أ)، ثم أعد الدخول |
| الموقع يعمل لكن الدخول يفشل دائمًا | `SUPABASE_SECRET_KEY` ناقص | أضِفه في Vercel ثم Redeploy |
| المتجر لا يظهر للزائر | حالة المتجر ليست `delivered` | من لوحة المالك → تسليم المتجر |
